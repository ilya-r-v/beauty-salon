# КР №3 · Салон красоты

Из корня репозитория выполните:

```sh
./scripts/init-env.sh
docker compose --env-file .env -f backend/docker-compose.yml up -d --build --wait
```

React и REST API доступны на http://localhost:8080. В первой сборке Docker скачивает зависимости. Порт приложения задаёт APP_PORT, порт PostgreSQL — DB_PORT в корневом .env. Healthcheck доступен по /actuator/health. После входа под администратором кнопка Swagger открывает /swagger-ui.html. Для вызовов API в Swagger можно также использовать Authorize с access-токеном.

Начальный администратор — +79990000005. При первом запуске возьмите временный пароль из BOOTSTRAP_ADMIN_PASSWORD в корневом .env и смените его в интерфейсе. Скрипт генерирует локальные секреты и сохраняет существующий .env. Для ручной настройки используйте .env.example. JWT_SECRET должен содержать минимум 32 байта. В разделе «Пользователи» можно сбросить пароли демонстрационных клиента и мастера. Браузер создаёт временный пароль, администратор передаёт его пользователю. Сервер хранит BCrypt-хеш и требует сменить пароль.

## Проверка на защите

1. Откройте health, войдите за администратора. Создайте запись, выбрав клиента, свободное время и услугу мастера. Приоритет высокий у ожидающей записи без предоплаты. Откройте карточку, внесите предоплату и проверьте смену приоритета и версии.
2. Откройте карточку в двух окнах, авторизовавшись в каждом. Сохраните изменения из первого, затем из второго. При конфликте версии нажмите «Перечитать».
3. Войдите за клиента, затем за мастера в отдельном окне. Клиент видит свои записи. Мастер видит своё расписание, меняет статус и ведёт заметки. Администратор редактирует карточку, архивирует, восстанавливает и может окончательно удалить выбранную запись.
4. Проверьте поиск, фильтры, сортировку и страницы. Экспортируйте CSV с текущим фильтром. Для обновления отредактируйте комментарий в файле, оставив код и версию. Для новой строки задайте уникальный code и свободный slotId того же мастера. Поле tags — массив JSON внутри CSV. После проверки примените файл. При ошибке строки исправьте файл и повторите проверку.
5. Выберите записи для массовой операции. В результате отдельно показаны успешные UUID и ошибки. Добавьте, закрепите, измените и удалите заметку. Откройте справочник, аналитику, пользователей и аудит. Поиск аудита принимает в том числе UUID записи и correlation ID.
6. В Swagger проверьте API. В PostgreSQL таблица flyway_schema_history содержит историю миграций. Docker Compose хранит данные PostgreSQL в именованном томе.

## Тесты

Для тестов используйте отдельный проект Compose и свободные порты. Из корня:

```sh
APP_PORT=18080 DB_PORT=15432 docker compose --env-file .env -p salon-tests -f backend/docker-compose.yml -f backend/compose.tests.yml run --build --rm tests
```

Обычная остановка сохраняет БД:

```sh
docker compose --env-file .env -f backend/docker-compose.yml down
```

Для разработки React при запущенном backend: в каталоге frontend выполните `npm ci` и `npm run dev`. Vite перенаправляет /api на localhost:8080. В сборке Compose React раздаёт Spring с того же адреса, что и API.

Для базы, созданной до перехода на Flyway через Go migrate, перед переносом сделайте резервную копию, сверьте схему с V1–V6 и вручную выполните baseline версии 6. Для уже управляемой Flyway базы baseline не нужен.
